# 状态与锁规范

## 统一状态

角色状态、Actor 状态、在线状态、当前操作、组队/跟随状态、交易状态、错误和更新时间必须汇聚到统一状态快照。Web、API、调度器和日志只读取统一投影，不得各自维护平行状态来源。

状态变更必须通过生命周期或能力编排入口完成，组队结束、被踢、真人退出队伍后要清理跟随状态并恢复普通调度。

## 统一锁

使用 `internal/foundation/lockhub` 的命名资源锁。调度器、Actor 容器、配置、角色创建/删除、数据库写队列、组队和 Web 操作必须使用明确用途的 lockhub 资源。

禁止新增裸 `sync.Mutex`、`sync.RWMutex`、同一资源的平行锁，或以临时布尔值替代资源锁。

锁的持有范围必须短，禁止在锁内执行长时间网络请求、等待 Actor 或进行不可控数据库操作。
