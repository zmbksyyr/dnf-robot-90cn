# 组队副本跟随诊断

副本房间内的位置同步走的是**客户端 UDP 数据面**（服务端只做内容无关转发）。
应用层负载的字段布局已经取证完成，解析与发送都已落地，机器人现在可以在副本房间里
按队长的 UDP 位置帧跟随，并把自身位置回报给队长客户端。本文档记录取证方法、
已验证的帧格式和现场工具，后续复现或排障按此执行。

## 已验证的应用层帧格式

2026-09-28 用本机客户端 + 服务端 + 机器人采样得到（样本固化在
`internal/protocol/s4a21/party_app_test.go`）：

- 应用层负载是 TQOS **type 2** 帧的 body（type 1 帧的 body 是 TLV 列表，位置同步不用）。
- body 布局：`[0]=0x01`、`[1]=子类型`、`[2]=0x00`、
  `[3:7]=CRC32(partyUDPCRCTable) over 明文[7:]`、`[7:]=明文逐字节用对端 codec 混淆`。
- 子类型 `0x07`（副本位置）：`u16 0x0211` + `u32 计数器` + 六个 `u32` 字段
  `[tick, state, baseX, baseY, x, y]`。`state=26` 为可用的移动帧，`state=0` 且
  `x/y=-1` 是复位广播。**`x`/`y` 就是角色在地图内的坐标**（实测按住右方向键持续移动时
  第一坐标变化、第二坐标不变；按住上下方向键时相反）。
- 子类型 `0x38`（城镇位置）：五个 `u32` 字段 `[1, 2, 区域, x, y]`。
- 混淆用的 codec 与 TQOS 控制帧相同（key/rotate），实测 key=`0x59`、rotate=`0`；
  接收端本来就会从帧里推导 codec，所以发送端可以自选 key。

## 实现

- `internal/protocol/s4a21/party_app.go`：应用帧解析/构造（含 CRC 校验）、codec 逐字节混淆。
- `internal/protocol/s4a21/party_udp.go`：
  - `SetPartyAppHandler` 把解码后的 `PartyAppPosition` 交给会话层；
  - `SendPartyPosition` 把机器人自身坐标以 `0x07` 帧广播给所有已知对端；
  - `StartPartyUDPExchange` 在服务端下发 `0x0B` 队伍端点名册后主动发起 TQOS 握手，
    这样机器人与机器人之间也能协商出 codec（真人客户端本来就会主动发起）；
  - `PartySlotOf` / `PartySelfSlot` / `PartyUDPReady` 供跟随层判断队长槽位与就绪状态。
- `internal/composition/backend/s4a21/dungeon_follower.go`：
  `handlePartyAppPosition` 只接受**队长槽位**发来的位置帧，镜像 `SET_USER_POSITION`，
  并把同一坐标通过 UDP 回报给队长（真人客户端据此绘制机器人移动）。
  队长槽位从实时名册解析，兼容 `CHANGE_HOST` 委任队长后槽位不重排的情况。
- 房间切换仍沿用 `START_MAP` / `FINISH_LOADING`；TCP 投影跟随
  （`USER_POSITION` → `SET_USER_POSITION`、`USER_AREA` → `SET_USER_AREA`）保留为兜底。

## 验证记录

- 单元测试：真实客户端采样帧的解码、构造回放（逐字节一致）、CRC 覆盖范围、
  错误 key/校验和拒绝、TQOS 握手自举（`party_app_test.go`、`party_exchange_test.go`）。
- 现场验证（机器人当队长、真人客户端当队员，副本 144）：
  机器人每 1.5 秒在两个坐标间移动并通过 UDP 广播，客户端画面上的机器人角色跟随移动，
  证明 **构造** 方向与真实客户端兼容。
- 实机测试：`S4A21_UDP_FOLLOW_LIVE=1 S4A21_TEST_ADDR=<addr> go test
  ./internal/composition/backend/s4a21/ -run TestLiveS4A21PartyUDPPositionFollow -v`
  在本地服务端上通过（两名机器人组队进图，队长广播位置，队员镜像成功），
  证明 **解析 + 跟随 + 回报** 全链路可用。
- 尚未完成：真人客户端当队长时由客户端键盘走位触发的一整轮现场跟随。
  客户端在副本内“新队长”状态下本次现场没有走起来（画面与 UDP 帧都停住），
  该路径的帧样例与解码已由上面的客户端采样夹具覆盖。

## 开关与样本

两个环境变量只在需要诊断时开启，日志有上限，不影响正常调度：

| 变量 | 作用 | 记录内容 |
|---|---|---|
| `S4A21_PARTY_UDP_TRACE=1` | UDP 全量追踪 | `S4A21_PARTY_UDP_TRACE_RX`（收到）、`_TX`（应答）、`_APP`（识别为应用负载的帧），单会话最多 4096 条、单对端 256 条、单包最多 512 字节 |
| `S4A21_PARTY_FOLLOW_TRACE=1` | 跟随追踪 | `S4A21_FOLLOW_TRACE_POS/AREA`（队长的 TCP 投影）、`_UDP_POS`（队长的 UDP 位置帧）、`_START_MAP`、`_FINISH_LOADING`、`_*_FAILED`，每次会话最多 512 条 |

另有**常开的有界样本**：不依赖任何开关，每个队伍对端的前 4 条应用负载都会写入

```text
S4A21_PARTY_UDP_APP_RX uid=<自己> remote=<对端> size=<原始长度> truncated=<是否截断> bytes=<十六进制>
```

单条最多 256 字节。副本内移动的应用层帧就出现在这些行里。

## 复现步骤

1. 启动服务端和真人客户端（机器人读取的 `inventory.db` 要与服务端同一份）。
2. 给机器人进程设置上面两个环境变量后启动机器人（在 `robot.exe` 所在目录，例如 PowerShell：
   `$env:S4A21_PARTY_UDP_TRACE=1; $env:S4A21_PARTY_FOLLOW_TRACE=1; .\robot.exe`）。
3. 真人客户端邀请机器人入队（或者按 `doc/代码审查记录.md` 的现场流程由机器人邀请真人）。
4. 进入一张普通/剧情副本：在第一张图里走动几秒 → 走到下一张图 → 再走动 → 退出副本。
5. 收集机器人目录下 `config/logs/robot.log`，按 `S4A21_FOLLOW_TRACE_UDP_POS`
   与 `S4A21_PARTY_UDP_APP_RX` 判读。

## 判读

- **`S4A21_FOLLOW_TRACE_UDP_POS` 在副本内出现**：UDP 位置面已打通，机器人在跟随队长。
- **只有 `S4A21_FOLLOW_TRACE_POS/AREA`**：只有 TCP 投影在起作用，检查 `APP` 样本里是否出现
  `0x07` 子类型帧、`S4A21_PARTY_UDP_SLOT` 槽位与 `PARTY_IP_INFO` 端点是否都可以看到。
- **完全没有 `S4A21_PARTY_UDP_TRACE_*`**：UDP 通道没有建立（检查队伍、`0x000B` 端点信息和
  `S4A21_PARTY_UDP_SLOT` 槽位日志）。
