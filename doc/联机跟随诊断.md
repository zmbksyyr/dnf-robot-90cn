# 组队副本跟随诊断

副本房间内的位置同步走的是**客户端 UDP 数据面**（服务端只做内容无关转发），
机器人目前只完成了 TQOS 握手与传输层帧处理，还没有解析/发送应用层负载，因此进图后队员站桩不动。
落地这部分不需要用户配合：维护者用本机客户端 + 服务端 + `S4A21ClientPatch`（GameGaurd 静态补丁、临时调试插件、Frida/静态分析）自行取证、还原并实现，用户只做最终验证。

## 自主取证（维护者执行）

1. 客户端侧：扩展 `S4A21ClientPatch` 的 GameGaurd 调试日志或加载一个临时调试插件，在客户端 UDP 收发点转储：远端地址、TQOS 帧类型/序列/路由、应用负载十六进制。
2. 交叉验证：用服务端源码确认转发语义（`TQOS` 只做内容无关转发），用静态分析确认客户端序列化布局。
3. 样本入库：把最小样本固化为单元测试夹具（帧类型 1/2 的 body 形状、应用负载字段偏移）。
4. 实现：`internal/protocol/s4a21` 增加应用负载解码/编码与单测；`s4a21` 适配层用队长状态驱动自身位置上报；房间切换仍沿用 `START_MAP` 投影。

## 开关

两个环境变量只在需要诊断时开启，日志有上限，不影响正常调度：

| 变量 | 作用 | 记录内容 |
|---|---|---|
| `S4A21_PARTY_UDP_TRACE=1` | UDP 全量追踪 | `S4A21_PARTY_UDP_TRACE_RX`（收到）、`_TX`（应答）、`_APP`（识别为应用负载的帧），单会话最多 4096 条、单对端 256 条、单包最多 512 字节 |
| `S4A21_PARTY_FOLLOW_TRACE=1` | TCP 跟随追踪 | `S4A21_FOLLOW_TRACE_POS/AREA`（队长的位置/区域投影）、`_START_MAP`、`_FINISH_LOADING`、`_*_FAILED`，每次会话最多 512 条 |

## 复现步骤

1. 启动服务端和真人客户端（机器人读取的 `inventory.db` 要与服务端同一份）。
2. 给机器人进程设置上面两个环境变量后启动机器人（在 `robot.exe` 所在目录，例如 PowerShell：
   `$env:S4A21_PARTY_UDP_TRACE=1; $env:S4A21_PARTY_FOLLOW_TRACE=1; .\robot.exe`）。
3. 真人客户端邀请机器人入队。
4. 进入一张普通/剧情副本：在第一张图里走动几秒 → 走到下一张图 → 再走动 → 退出副本。
5. 收集机器人目录下 `config/logs/robot.log`。

## 判读

- **`S4A21_FOLLOW_TRACE_POS/AREA` 在副本内出现**：服务端会把队长的 TCP 位置投影给队员，
  跟随应基于 TCP 修复（检查镜像发送是否失败）。
- **副本内完全没有该日志**：说明位置只在 UDP 数据面，需要按 `S4A21_PARTY_UDP_TRACE_APP`
  的十六进制样本还原应用负载格式（位置/朝向等字段），再实现解析与发送。
- **完全没有 `S4A21_PARTY_UDP_TRACE_*`**：UDP 通道没有建立（检查队伍、`0x000B` 端点信息和
  `S4A21_PARTY_UDP_SLOT` 槽位日志）。

## 当前状态

- TQOS 握手、帧拆分、ACK、编解码候选与槽位解析已实现并有单测（`internal/protocol/s4a21/party_udp*.go`）。
- 应用层负载的解码/编码与发送尚未实现；阶段六按上面的“自主取证”流程落地，完成后在本文件补充最终字段表与验收步骤。
