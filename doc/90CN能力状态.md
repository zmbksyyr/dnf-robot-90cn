# 90CN 能力状态

本文档记录当前仓库对应的 DNF90（90CN）模拟端能力边界。状态只描述本仓库已经实现的代码和已完成的验证，不代表服务端本身具备同名功能。协议实现依据 90CN 服务端源码（`DNF90-source-oneclick/go-server`，见 `internal/services/dnfbridge` 与 `internal/modules/dnf/protocol`）；服务端契约摘要见 [`90CN适配笔记.md`](90CN适配笔记.md)。

## 已实现并实机验证（2026-09-30，本机运行中的 DNF90 服务端）

- 运行时解析：读取一键工程目录（或 runtime 目录）的 `runtime/config/instance.json`，解析管理端（`server.adminListen`/`server.adminToken`）、SQLite 路径与 PVF 路径；游戏端口按 `data/dnf/channel_info.etc` 推导（game 端口 = 10000 + 频道号），并按账号稳定分配频道；可用 `game_port` 覆盖为单端口。
- 账号绑定：`POST /local/client-account`（`X-Admin-Token`）把当前进程 PID 绑定到机器人账号；注册、拨号与首个回包在一个临界区内完成。实机日志确认每个连接 `session_account_bound=true`。
- 会话流程：绑定登录（class0/op1 CHANNELINFO → class1/op1 590 字节端点请求 → class1/op1 成功）→ 花名册（class0/op2）→ 按槽位选角（16 字节 op4 形态）→ op143 初始城镇检查点（progress=36）→ class0/op24 城镇转场 → op36 落点 → op1276 心跳（选角后应答）→ op3 退出。
- 城镇移动：op36（16 字节当前形态）与 op35（7 字节）；实机确认 `game-town-set-user-area-committed`（town 38 的多个区域，含 area 1 Seria 房间与 area 3 Elvengard Hendon；频道 19/251）。
- 角色创建/删除/查重协议（op5/op6/op692）实机验证：创建返回 slot，删除后花名册刷新为空（`game-delete-success`）。
- 持久化（第一阶段）：启动扫描（`dnf_accounts`/`dnf_characters` 严格 `前缀+UID`）、等级/经验/成长写入、`tutorial_completed=1` 标记（新角色跳过地城教程、直接进入城镇路线）、角色档案读取、危险删除（`dnf_*` 逐表清理）、人口统计（账号/角色/职业/性别/区域）、SQLite 健康校验（`dnf_*` 表存在性）。
- 装备/时装生成（第二阶段）：按职业/等级/稀有度从 PVF 目录选装并写入 `dnf_equipments`/`dnf_equipment_entries`/`dnf_equipment_entry_extra`，与服务器初始装备同构：43 字节 entry 摘要（槽位/物品 ID/create value/耐久）+ `source=pvf_create_equipment_list`、`pvf_path`、`durability`、`equipment_type`（从 `.equ` 读原生类型号）、武器强化 `ext_data0`；12 个穿戴槽（含耳环 13）+ 10 个时装槽（`current_exe_equipment_type` 直接外观槽）。本机实机验证：建号后写入 10 时装 + 10 装备行，服务端选角/城镇路线无错误。
- 任务门禁（第三阶段）：启动与建号时为每台机器人写入固定门禁集合（PVF 世界地图持久门禁 + 进行中/任务连接门禁 + **全部城镇区域的 `[need quest]` 需求**），写入 `dnf_quests`/`dnf_quest_states`（`state_group='states'`，completed/active），并保证同一任务不会同时处于两种状态。本机实机验证：门禁写入后 op36 落点提交成功（town 38 / area 3 / Elvengard Hendon），修复了此前 "target_area_has_pvf_quest_requirement" 拒绝。
- 宠物/神器（第四阶段）：按职业/等级/概率选宠（`capability/equipment.SelectPet`）并写入原生 `dnf_pets`/`dnf_pet_entries`/`dnf_pet_artifacts` 与装备槽 26 的 46 字节穿戴行（serial 同时写 +5 与 +24），宠物条目来源固定为装备列表 3 / 槽位 26（服务端一致性校验要求）。概率按角色 ID 稳定哈希，避免重启重掷；启动对账为缺宠物的存量机器人补齐。实机验证：选角后服务端依次发送 creature item refresh、op105 生物状态表、op102 成长状态并开启城镇成长时钟，断线结算 `game-pet-satiety-settled` 成功（此前穿戴来源写错会以 `equipped creature persistence is inconsistent` 失败）。
- PVF 列表解析加固（本轮修复）：`equipment/equipment.lst` 存在错位行，原按固定步长配对会丢失列表尾部（神器与大量装备）。改为遇到非 id/路径对时向后重同步，目录从 122,878 件恢复到约 14 万件（含神器红 70 / 蓝 52 / 绿 36、宠物 892）。
- PVF：90CN `Script.pvf`（protected_nkpi）字符串池解码；本机实测 1,057,913 路径、257 城镇区域、122,878 装备/装扮、45,584 可叠加、16 职业属性表、99 等级阈值、任务门禁 24/926。

实机验证方式：`CN90_LIVE_PROTOCOL=1 go test ./internal/composition/backend/cn90/ -run TestLiveRobotProvisionAndSession -v`（对运行中的服务端完成 建号→写等级→登录→选角→城镇→心跳→移动→删除 的完整周期并清理）。

## 已实现但未实机验证

- 危险删除（`dnf_*` 全表清理）：单元测试覆盖，尚未对真实库执行过删除。
- 多机器人并发登录下的频道路由/绑定串行化：单元与单账号实机验证，未做多账号并发压测。
- 人口统计报告：实机读取通过（当前 0 个机器人账号），尚未覆盖大规模机器人数据。

## 未实现或明确置空

- 战斗属性离线重算：依赖服务端选角时的 PVF 重算与修复；机器人只写装备行，不写 `stat_*`。
- 摆摊（分解机/附魔摊）、服务器公告、喊话、组队/工会邀请、副本跟随与副本移动、拍卖、邮件、服务控制、诊断。
- Linux 运行：PID 解析缺失时只能使用服务端回退账号（`DNFBRIDGE_ACCOUNT_ID` 或 `dnf:1`）。

上述能力在适配器描述符中必须保持关闭并给出原因，Web 端隐藏或置灰；后续阶段逐项实现后再更新本文档与 `internal/composition/backend/cn90/descriptor.go`。

## 尚未验证

- 长时间高在线人数运行的稳定性（连接数、SQLite 锁竞争、频道分配）。
- 真实玩家与机器人的交互呈现（同频道看到机器人、宠物外观、组队邀请）。
- 装备/时装/宠物在客户端中的最终外观表现。

## 维护规则

- 新增或修复 90CN 能力时，同步更新本文档和 `internal/composition/backend/cn90/descriptor.go`。
- “已验证”必须有可复现的服务端/客户端验证记录；仅编译通过或单元测试只能标记为“已实现”或“未验证”。
- 版本特化（opcode、表名、路径、PVF 规则）只允许出现在 `internal/composition/backend/cn90` 与 `internal/protocol/cn90`。
