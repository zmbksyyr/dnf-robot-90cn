# 90CN 能力状态

本文档记录当前仓库对应的 DNF90（90CN）模拟端能力边界。状态只描述本仓库已经实现的代码和已完成的验证，不代表服务端本身具备同名功能。协议实现依据 90CN 服务端源码（`DNF90-source-oneclick/go-server`，见 `internal/services/dnfbridge` 与 `internal/modules/dnf/protocol`）。

## 已实现（协议接入，尚未实机验证）

- 运行时解析：适配器读取一键工程目录（或 runtime 目录）下的 `runtime/config/instance.json`，解析频道监听地址（`server.channelListen`）、管理端（`server.adminListen` / `server.adminToken`）、SQLite 路径（`database.path`）与 PVF 路径（`game.pvfPath`）；游戏端口默认按频道目录推导（game 端口 = 10000 + 频道号），可用 `game_port` 覆盖。- 账号绑定：按 90CN 登录器的本机绑定流程调用 `POST /local/client-account`（`X-Admin-Token`），把当前进程 PID 绑定到机器人账号；注册、拨号与首个回包在一个临界区内完成，避免多机器人并发登录时串号。
- 传输接入：出站使用 13 字节 legacy game 帧（服务端分流器会把 op1/op4/op5/op36/op1276 等按 raw upper 处理）；入站解析 server16 的 16 字节 upper 头（`protocol.gameUpperHeader=server16`）。
- 会话流程：绑定登录（class0/op1 CHANNELINFO → class1/op1 590 字节端点请求 → class1/op1 成功）→ 花名册（class0/op2）→ 按槽位选角（16 字节 op4 形态）→ op143 初始城镇检查点（progress=36）→ 等待 class0/op24 城镇转场 → 可选 op36 落点与在线状态上报 → op1276 心跳保活（选角后应答）。
- 城镇移动：op36 使用当前客户端的 16 字节形态（town/area/x/y/direction + 零不透明尾），op35 使用 7 字节形态；区域切换以 class0/op23（USER_AREA）通知为准。
- 建角/删角/查重协议：op5（job + 名字 + 8 字节外观选项）、op6（slot + 名字）、op692（名字查重），并已接入机器人创建/清理代码路径。
- 频道发现：从 `channel_info.etc` 目录（由服务端解析）推导候选 game 端口；当前实现按实例 `server.channelListen` 的推导结果与显式覆盖选择端口，尚未做多频道分配。

## 未实现或明确置空

- 持久化层仍沿用 S4A21 的库表（`characters`/`character_inventory_items` 等），尚未适配 90CN 的 `dnf_*` 表（`dnf_characters`、`dnf_character_stats`、`dnf_inventory_items`、`dnf_equipment_entries`、`dnf_pets`、`dnf_quests`、`dnf_skills`）；因此启动扫描、装备/时装/宠物套装、等级/成长写入、任务门禁、清理、危险删除、人口统计在本阶段不可用。
- 摆摊（分解机/附魔摊）、服务器公告、喊话、组队/工会邀请、副本跟随与副本移动。
- 账号创建（`dnf_login_accounts` 由登录器/控制端写入）：机器人直接用账号 id 绑定，无需该表。
- 拍卖、邮件、服务控制与诊断。

上述能力在适配器描述符中必须保持关闭并给出原因，Web 端隐藏或置灰；后续阶段逐项实现后再更新本文档与 `internal/composition/backend/cn90/descriptor.go`。

## 已验证（本机资源）

- PVF 读取：本机 90CN 运行包 `Script.pvf`（protected_nkpi，约 111 MB）可完整解析：1,057,913 个文件路径；城镇目录 257 项（238 项有可用移动几何）；装备/装扮 122,878 项、可叠加 45,584 项；16 个职业的属性表全部可用（无兜底职业）；等级阈值 99 项；任务门禁（完成 24 / 进行中 926）。验证方式：`CN90_TEST_PVF=<Script.pvf> go test ./internal/composition/backend/cn90/ -run TestLiveReadAllCatalogs -v`。

## 尚未验证

- 与真实 DNF90 服务端的实机联调：绑定登录、选角、初始城镇路线、op36/op35 移动、心跳保活。当前只有帧结构/结果解析的单元测试。
- 多机器人并发登录时 PID 绑定的竞态窗口（当前用“注册 + 拨号 + 首个回包”串行化，未实机压测）。
- 非 Windows 平台：PID 解析缺失时只能使用服务端回退账号（`DNFBRIDGE_ACCOUNT_ID` 或 `dnf:1`），不能按账号隔离。

## 维护规则

- 新增或修复 90CN 能力时，同步更新本文档和 `internal/composition/backend/cn90/descriptor.go`。
- “已验证”必须有可复现的服务端/客户端验证记录；仅编译通过或单元测试只能标记为“已实现”或“未验证”。
- 版本特化（opcode、表名、路径、PVF 规则）只允许出现在 `internal/composition/backend/cn90` 与 `internal/protocol/cn90`。
